# 小黑盒后台：Cloudflare 人工处理版

这个版本将后台界面、任务配置、人工需求分析、草稿审核和操作日志接入现有工作台。它沿用工作台的登录、D1 数据库和 AI 设置，不依赖本机 Python 进程。

## 使用顺序

1. 登录工作台，打开侧栏「小黑盒后台」。
2. 在「任务配置」中保存主题词、需求词、排除词与回复模板。规则仅筛选你手动录入的内容：两组关键词都要命中，组内任意命中即可，排除词优先。命中不代表用户确有需求。
3. 在「人工需求」中录入或导入已获准使用、去除个人标识的信息，确认使用权。需要模型分析时，主动点击分析按钮；调用工作台现有模型，受现有预算和次数限制，可能产生 API 费用。
4. 在「草稿审核」选择需求，检查原文与模型依据，采用 AI 草稿或已保存模板，修改后保存为待审核，再批准或退回。**批准只保存审核状态，不会发送。**
5. 在「操作日志」查看服务器记录的配置、需求、分析和审核事件。日志只含动作、时间和记录 ID，最多保留最近 300 条。

原文被修改、重新分析或删除后，旧审核会显示过期，不能继续批准；需要基于当前原文重新保存草稿。不同设备同时编辑发生冲突时，请重新读取云端版本再决定修改，系统不会静默覆盖其他设备的结果。

## 本轮没有部署的功能

本轮没有小黑盒账号绑定、自动读取帖子或评论、回帖、关注、私信或外部联系方式投递。平台状态显示「未接入」。之前的测试用户和模拟发送统计不再作为默认后台显示。

电脑关机后，已经保存的配置、需求、审核和日志仍在 Cloudflare 上可用。本模块没有后台营销任务，也不会持续自动调用模型。

## GitHub 与 Cloudflare 更新

现有 GitHub 仓库为 `a2959725348/MOYA-`，生产分支为 `main`，Cloudflare Pages 项目为 `moya`。

- 将项目根目录的源码更新推送到同一仓库即可触发现有 Git 自动部署；无需另外向 Pages 上传 ZIP。
- 主要改动是 `src/`、`server/`、`cloudflare/app.mjs`、相关测试和本文档。保留仓库现有 `functions/`、`wrangler.jsonc`、包文件及构建设置。
- 构建命令保持 `npm run build`，输出目录保持 `dist`。Pages 自动处理根目录的 `functions/`。
- 沿用生产环境的 `DB` 绑定、`VAULT_KEY` 和其他已有变量。不用重新创建数据库、不用导入 SQLite、不用执行新的迁移 SQL、不用修改密钥。
- 不要上传 `.env`、`.dev.vars`、`vault.key`、`workbench.sqlite`、`data/`、`node_modules/` 或私人备份 ZIP 到 GitHub。源码 ZIP 应先解压，不能把 ZIP 本身当作仓库源码。

若自动发布凭据失效，使用自己电脑的 PowerShell 在项目目录运行 `git -c http.sslBackend=openssl push origin main`，完成 GitHub 官方登录即可。这只为这条命令选择 TLS 实现，仍验证证书，不改变全局 Git 配置。Pages「部署」页可查看该提交对应的构建日志；部署绿色成功后刷新网站。

## 数据与备份边界

新配置和日志存储在 D1 原有 `kv` 表，新审核记录存储在原有 `records` 表的独立集合中。本轮不改变数据库表结构。旧工作台 JSON 备份仍可使用，但没有扩展为导出本模块配置、审核和日志；完整备份时应另外保留 D1 数据库导出。不要用空数据库替换生产数据库。
