# Demand analysis MVP implementation plan

Goal: Replace the unused market screen with a small, verifiable demand-analysis and voluntary-consultation workspace. User authorized implementation and deployment on 2026-10-09. Heybox collection remains pending separate authorization.

Architecture: React UI, shared validated domain module, existing Fastify backend and Cloudflare Pages Functions / D1. Use existing encrypted AI key and limits. Store new JSON record collections in existing records table; no destructive migration. Borrow OpenMagpie's semantic filtering, deduplication and evidence approach; copy no third-party implementation.

Tech stack: Existing Node 24, React, TypeScript, Zod, D1, SQLite, Vitest. No new dependency.

Spec: This plan is the approved small-version design expressed as concrete contracts. Existing authentication, quota, study and sync behavior must remain working. No scraping, automated outreach, user profiling, public financial promotion or guaranteed payment claims. Import only rights-approved deidentified excerpts. Test samples must be labelled synthetic. AI judgment is advisory and must include source evidence. Tutorial text stays factual, private and reviewable; never claim Roogoo guarantees ChatGPT subscription.

## Task 1: Backend and behavioral tests

Own server/, cloudflare/, tests/server-demand*.test.mjs, tests/cloudflare-demand*.test.mjs, tests/demand*.test.mjs. Do not change UI. Add shared demand domain/service modules as needed and schema collections `demands`, `consultations`. Read existing authentication, store transaction, vault, network transport, backup and chat limit implementations before integration. Keep all routes authenticated and same-origin using existing middleware.

Demand input: `{text: string (trimmed 1..4000), source: 'manual'|'voluntary'|'sample', sourceUrl: string (optional default '', only http/https without credentials), rightsConfirmed: true, expectedCategory?: category|null, status?: 'pending'|'approved'|'dismissed'}`. Collections and state also expose `analysis: null|Analysis`; analysis is server-owned and cannot be set/edited through generic CRUD or import. Text and URL edits invalidate analysis. Reject input containing obvious email, mainland mobile number or card number with an actionable deidentification message. Do not send identity/contact fields to AI. Restrict URL credential/query leakage; no network access to sourceUrl. Dedup fingerprint normalized lowercase whitespace text + canonical sourceUrl, server enforces all create/import paths and edit collisions. Exact duplicate means existing id is reused / skipped, not extra record. Clearly return import counts.

Category enum: `subscription_question`, `payment_failure`, `api_credits`, `card_question`, `alternative`, `already_solved`, `promotion`, `unrelated`, `uncertain`.

Analysis `{category, summary (1..600), evidence: string[] (1..3, each nonempty <=600 and exact substring of demand.text), reason (1..1000), draftReply (<=2000), confidence: number (0..1), model, analyzedAt, tokens?: number, cost?: number, currency?: 'CNY'|'USD'}`. Explain negation/already solved/advertisements in system prompt and prohibit inferring private attributes. Text is untrusted quoted data, never instructions. Returned JSON must validate strictly; fabricated evidence / incomplete provider result must not be stored. Financial content: free tutorial can be discussed but no guarantee, no regional bypass, no API-prepaid compatibility claims, no unsolicited contact solicitation.

Consultation `{question: string (1..4000), alias: string (0..80, optional default ''), status: 'new'|'answered'|'closed' (default new), note: string (0..2000 default ''), consentConfirmed: true}`. No contacts/card credentials stored. Generic CRUD validated; state/backup include both collections.

Routes: POST `/api/demands/import` body `{items: DemandInput[]}` length1..20, all validated before writes, transaction/withStore, response `{imported:number,duplicates:number,records:Demand[]}`. POST `/api/demands/:id/analyze` body `{}`; 404 missing, 400 not configured/input invalid, 429 shared request/budget limit, 502 safe Chinese JSON on upstream/error/invalid output, 409 if source modified/deleted while response pending, 401 revoked session. Return `{record:Demand}` after committed analysis. One paid call only, outside D1 retry callbacks; 45second abort timeout for call and body. Validate content-type and provider finish_reason to prevent HTML/partial JSON. Max output tokens bounded by min(existing maxTokens,2048); for DeepSeek set thinking.type disabled; JSON object output requested. Use approved network transport and existing vault/fallback keys.

Share existing `chatCounter` daily request reservation atomically between analysis and study chat, and share known cost budget across chatMessages and demands.analysis. Store costs only when provider usage exists; missing usage stays unknown, no fabricated zero. Existing budget is estimated prior-call check, not guaranteed billing cap. Reanalysis counts again, overwrites record only after valid response and unchanged input. Session validity is rechecked before persistence. Generic CRUD cannot manufacture or alter model results; backup restore may carry legitimate validated analysis.

Meaningful TDD: first write and run failing tests, then implement. Unit fixtures for schema/PII/evidence; both real store HTTP backends test import validation atomicity, dedup (incl update), authenticated analysis success, malformed/HTML/provider rejection, invented evidence, no key leakage, revoked session, edit during paid call, shared limit/cost and concurrency exactly-once for Cloudflare. Tests should use mocked provider transport but real route/store boundaries. Report RED and GREEN commands and results. Run appropriate existing backend tests once integrations pass.
